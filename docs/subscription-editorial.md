# 구독 내 작성 → 저장소 콘텐츠 발행 v1.0

기준일: 2026-10-26. 상태: 로컬 구현, 운영 미반영.

## 목적과 범위

사용자 요청: “쿠팡링크를 붙일 만한 글을 꾸준히 써야겠어”, “깃헙을 보든지 코덱스를 이용하든지 그걸 니가 알아서 좀 해줘”. 유료 모델 API 비용 없이 ChatGPT에서 출처 확인한 글을 저장소에 작성하고 기존 허브 화면으로 발행한다. 새로운 서버, DB 테이블, API 키는 추가하지 않는다. 기존 유료 생성기와 cron은 재개하거나 변경하지 않는다. 이 변경만으로 전체 사이트가 무비용 또는 완전 자동 운영으로 전환되는 것은 아니다.

## 구현 선택

- `lib/hubs/editorial/index.ts`: 출처 확인 콘텐츠와 순수 병합 함수. 같은 허브/slug에서는 저장소 글이 DB 글보다 우선한다. DB 장애에도 해당 글을 반환한다.
- 기존 주소·허브·화면 구조·광고 고지를 유지한다. 글별 허용 제휴 슬롯을 기존 등록 링크에서만 선택한다.
- 사이트맵은 주소를 중복 등록하지 않고 실제 편집일을 반영한다.
- 글 추가는 기존 허브 키에 HubDocument 한 건을 등록한다. `updatedAt`은 실제 수정일, `sourceNote`는 확인한 원자료/확인일, `affiliateSlotIds`는 본문 판단에 필요한 기존 슬롯만 지정한다. 빈 배열은 광고 링크 없음이다.
- 가격/재고/최저가/사용 경험을 만들어 쓰지 않는다. 아직 등록되지 않은 허브를 여기에만 추가하지 않는다.

## 첫 원고 선택과 사실 근거

네이버 인증 화면에서 버즈4 단품 구매 글의 검색 유입(최근 30일 클릭104, 노출2216)을 확인했다. 이것은 쿠팡 클릭·주문 데이터가 아니다. 사용자 수익3000원과 연결해 전환율을 계산하지 않았다.

대상: `/hub/galaxy-buds4/single-bud-replacement`. 기존 URL과 제목을 유지해 허브의 제목 기반 연결을 보존한다. 한쪽 분실 → 모델/좌우 확인 → 단품 견적과 새 세트 비교 → 공식 커플링 절차로 개정했다. 액세서리 광고 대신 기존 `buds4-body` 슬롯만 제시한다.

삼성전자서비스 https://www.samsungsvc.co.kr/solution/25084 (표시일2026-04-03, 확인2026-10-26): 버즈4/4프로의 새/기존 이어버드 커플링은 케이스를 열고 뒷면 버튼7초. 파란 점멸 후 소등 완료, 빨간 점멸 실패. 원문 검색 색인에서 해당 모델의 설명을 확인했다. 직접 open은502로 실패해 실시간 페이지 렌더를 확인했다고 주장하지 않는다. 가격·재고는 확인되지 않아 제외했다. 구매 비교 기준은 편집 판단이며 삼성의 구매 권고로 표현하지 않는다.

## 검증과 공개 경계

`node scripts/test-editorial-content.cjs`: DB 실패 시 콘텐츠 유지, 동일slug 우선순위, 타 문서 보존, 링크 범위/빈 링크 제외, 사이트맵 중복과 날짜 확인.

`npx tsc --noEmit`, `npm run build`를 로컬 실행한다. 운영 DB 쓰기/AI 생성 함수 호출/자기 제휴 링크 클릭은 하지 않는다. AGENTS.md 승인 경계에 따라 git push와 운영 배포는 별도 승인 후 수행한다. 배포 후 해당 URL·사이트맵·광고 고지·모바일 화면을 확인해야 운영 검증 완료다.

## 후속 운영

검색 유입이 확인된 기존 제품 글부터 개선한다. 유입 없는 새 글을 무작정 양산하지 않는다. 다음 우선 조사 후보는 버즈 충전 케이스와 보호 케이스 구별, 기기 충전 문제 중 실제 구매가 필요한 조건이다. 공식 출처와 기존 글 중복을 확인한 다음 채택한다. 멜론·정책 안내에 무관한 상품을 붙이지 않는다.

7일/28일 단위로 네이버 페이지별 클릭·노출과 실제 쿠팡 보고서를 각각 확인한다. 현재 `/go`는 리다이렉트만 제공하며 페이지별 제휴 클릭 계측은 구현되지 않았다. 구매전환이나 매출 상승은 아직 검증하지 않았다. 작성 자동화·push·배포 일정은 아직 설정하지 않았다.

## v2.3 — 한 글에서 문제를 해결하는 편집 기준


최신 편집 원칙 — 독자의 막힌 결정을 한 글에서 해결:
- 각 글은 독자가 실제로 막히는 질문 하나를 정의하고, 검색 상위 글·공식 문서·커뮤니티에서 따로 찾아야 하는 정보를 검증해 한 글에서 연결한다. '다른 데 없는 정보'를 만들려고 사실을 발명하거나 최초·유일을 미검증 주장하지 않는다. 차별점은 출처를 종합한 조건별 판단, 실행 순서, 비교표, 계산 방법, 예외와 후속 행동에서 만든다.
- 조사 기록에 독자 상황/핵심 질문, 기존 자료의 빈틈, 이 글에서 추가하는 실용적 가치, 근거 URL을 남긴다. 기존 글의 요약에 그치면 발행하지 말고 보강하거나 통합한다.
- 본문 안에서 결론→상황별 선택→정확한 모델/호환 조건→총비용(별도 구매·설치·유지비 포함, 미확인 금액은 명시)→실행 순서→예외/안 사도 되는 경우→구매 전 확인 목록을 질문에 필요한 만큼 완결한다. 순서와 항목은 기계적으로 늘리지 않는다. 독자가 다시 검색해야 하는 핵심 답을 내부 링크 뒤로 미루지 않는다. 내부 링크는 더 깊은 근거와 다른 상황의 선택 자료로 사용한다.
- 상품 CTA는 본문에서 충분히 판단한 뒤 판매 페이지에서만 확인할 현재 옵션/가격/구성 등을 확인하도록 배치한다. 정보 부족이나 결론 숨기기를 클릭 유도로 사용하지 않는다. 본문 모델과 광고 모델이 다르면 정확히 구분하고 일치 상품처럼 권하지 않는다.
- 발행 직전 '독자가 이 글만 읽고 다음 행동을 정할 수 있는가', '유사 글을 합친 수준을 넘어 조건/비용/예외를 연결했는가', '광고를 빼도 유용한가'를 검수한다. QuickChoice UI만 추가한 것을 원고 전체의 정보 완결성 충족으로 간주하지 않는다.
