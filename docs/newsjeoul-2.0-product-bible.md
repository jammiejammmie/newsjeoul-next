# 뉴스저울 Product Bible v0.1 (확정 대기)

> 이 문서는 뉴스저울의 헌법이 될 문서다(v1.0 확정 전 초안). 확정되면 앞으로 모든 구현, 디자인, AI, DB, SEO, 운영은 이 문서를 기준으로 판단한다.
> 이 문서가 끝나기 전까지 SQL/DB/API/Workflow/Pipeline/Frontend/Backend/Commit/Build를 하지 않는다.
> 기존 산출물(`architecture.md`, `topics_entities_schema.sql`, `AGENTS.md`)은 폐기하지 않는다 — 참고자료로 유지하되, 이 문서와 충돌하면 이 문서가 이긴다.
> 이 문서는 Node/Topic/Entity/DB에서 시작하지 않는다. **사람**에서 시작한다. 구조는 사람을 위한 도구일 뿐이다.

뉴스저울은 뉴스 사이트가 아니다. 위키가 아니다. 검색엔진이 아니다. AI 요약 서비스가 아니다. **세상의 모든 지식을 탐험하는 플랫폼**이다. 성공한다면 사람들은 이걸 "뉴스를 보는 사이트"라 부르지 않고 "세상을 탐험하는 사이트"라 부르게 된다.

---

# 0. 철학

### WHY
정보는 이미 차고 넘친다. 부족한 건 정보가 아니라 **맥락**이다. 뉴스는 낱개로 소비되는 순간 문맥을 잃는다 — "이게 왜 중요한지, 무엇과 연결되는지, 어디로 이어지는지"가 사라진 채 헤드라인만 스쳐 지나간다. 뉴스저울은 그 잃어버린 맥락을 복원한다.

### Mission
세상에서 일어나는 일들을 서로 연결해, 사용자가 하나를 알고 싶어 들어와도 결국 세상 전체의 흐름을 이해하게 만든다.

### Vision
10년 뒤, "뉴스저울에서 찾아봐"가 "구글에서 검색해봐"와 동급의 습관이 된다. 단, 검색이 아니라 **탐험**의 습관으로.

**장기 비전(최상위 한 문장)**: 뉴스저울은 뉴스를 소비하는 서비스가 아니라, 시간이 흐를수록 AI와 함께 스스로 더 똑똑해지고 가치가 커지는 살아있는 지식 데이터베이스를 만드는 프로젝트다.

### Core Principles
1. 모든 페이지는 통로다. 목적지가 아니다.
2. 링크의 개수가 아니라 "왜 연결되는가"가 다음 클릭을 만든다.
3. AI가 만들고, 사람은 예외만 고친다.
4. 정확함보다 "따라갈 수 있음"을 우선한다 — 단, 사실관계 왜곡을 허용한다는 뜻은 아니다. 루머는 반드시 루머로 표기한다.
5. 기사는 휘발되고, 지식은 축적된다.
6. "뉴스저울"이라는 이름을 떼도 성립하는 구조를 만든다 — 뉴스는 지금의 재료일 뿐, 본질이 아니다.
7. 계층(트리)을 만들지 않는다. 무엇도 "최상위"가 아니다 — 전부 대등하게 연결된다.
8. **데이터는 죽지 않는다(Data Never Dies).** 오늘의 기사는 소비되고 사라지는 콘텐츠가 아니라 미래를 위한 데이터 포인트다 — 원칙 5("기사는 휘발되고 지식은 축적된다")는 기사의 *현재성/관심*이 휘발된다는 뜻이지, 데이터 자체를 버린다는 뜻이 아니다. 삭제보다 비활성화, 덮어쓰기보다 버전관리, 수정보다 History를 우선한다. 오늘 저장한 데이터는 1년·5년·10년 뒤 새로운 맥락에서 다시 검색되고 다른 데이터와 연결되며 새로운 가치를 만든다 — 과거 데이터를 잃는 것은 미래의 자산을 잃는 것이다.
9. **지식은 계속 자란다(Living Knowledge) — Data Never Dies의 확장.** Data Never Dies가 "데이터를 버리지 않는다"라면, Living Knowledge는 "같은 데이터도 AI가 발전할수록 계속 더 똑똑해진다"는 원칙이다. 데이터는 그대로지만 지식은 계속 성장해야 한다 — 새 모델(GPT-7, GPT-8...)이 등장하면 과거 데이터를 다시 분석하는 것은 특별한 이벤트가 아니라 뉴스저울의 기본 동작이어야 한다. 앞으로 모든 설계는 다음 4가지 질문을 통과해야 한다: ① 이 데이터는 미래 AI가 다시 분석할 수 있는가? ② 새로운 관계를 발견할 수 있는가? ③ 새로운 Summary를 만들 수 있는가? ④ 새로운 검색 의도에서도 다시 발견될 수 있는가?

### 절대로 하지 않을 것
- 낚시성 제목, 어그로 카피 — 신뢰가 유일한 자산이다.
- 정치적 편향 노출 — 침묵지수는 "누가 안 다뤘나"의 관찰이지 "누가 옳은가"의 주장이 아니다.
- 사용자 데이터를 광고 타겟팅 이외 목적으로 오남용.
- 미확인 루머를 확정 사실처럼 표기.
- 내용 없는 페이지 양산(SEO 스팸).
- 연결(탐험) 콘텐츠와 광고를 시각적으로 뒤섞는 것.

### 성공 정의
사용자가 이 서비스를 "뉴스 사이트"가 아니라 "세상을 탐험하는 도구"로 표현한다. 정량 노스스타: **세션당 탐험 깊이(페이지뷰/세션)**, **N일 재방문율**.

### 실패 정의
세션당 페이지뷰가 일반 뉴스사이트 수준(1~2)에 머무른다. 페이지가 위키 짝퉁처럼 읽힌다. 트래픽이 개별 기사 페이지에만 몰리고 더 깊은 탐험으로 이어지지 않는다.

# 1. 사람 — 왜 클릭하고, 왜 떠나고, 왜 돌아오는가

구조를 설계하기 전에 사람을 먼저 이해해야 한다. 아래 각 질문의 답이 뒤에 나오는 모든 구조적 결정의 근거다.

- **왜 궁금해하는가**: 정보가 갭(gap)으로 제시될 때 — 완결된 답이 아니라 "이것과 저것이 왜 연결되는지" 반쯤 열린 문장이 궁금증을 만든다.
- **왜 비교하는가**: 인간은 절대값보다 상대값으로 세상을 이해한다 — 경쟁사, 유사 사건, 이전 사례가 옆에 있어야 지금 보는 것의 크기를 가늠할 수 있다.
- **왜 반박을 읽는가**: 자신의 판단이 맞는지 검증하고 싶은 욕구 — 같은 사건의 다른 헤드라인, 다른 해석이 옆에 있으면 계속 머문다.
- **왜 저장하는가**: 지금 당장 답을 다 소화하지 못했지만 이 흐름을 놓치고 싶지 않을 때 — "이 이슈가 어떻게 되는지 계속 보고 싶다"는 욕구.
- **왜 공유하는가**: "나만 아는 걸 남에게 보여주고 싶은" 정보 우월감 + 숫자로 검증된 놀라움(침묵지수, 예상외 연결).
- **왜 친구에게 보내는가**: 그 친구와 관련 있다고 판단했을 때 — 즉 "이 사람에게도 맥락이 있다"는 확신. 콘텐츠가 한 사람만을 위한 것이 아니라 "이야기"로 전달 가능해야 공유된다.
- **왜 다음 링크를 누르는가**: 지금 읽은 것이 완결되지 않았다고 느낄 때. 완벽하게 요약된 글은 오히려 클릭을 멈추게 한다 — 역설적으로 "이 답은 다른 질문을 남긴다"는 여지가 다음 클릭을 만든다.
- **왜 검색 대신 탐험을 선택하는가**: 검색은 "내가 이미 아는 질문"에만 답한다. 탐험은 "내가 물을 줄도 몰랐던 질문"을 발견하게 해준다 — 이게 우리가 검색엔진과 근본적으로 다른 지점이다.

이 답들을 관통하는 하나의 원리: **완결된 답은 이탈을 만들고, 열린 답은 탐험을 만든다.** 뒤에 나오는 모든 구조(Relation의 explanation, Node의 3축 구조, Update 피드)는 전부 이 원리를 기술적으로 구현한 것이다.

# 2. 심리학 — 사람의 행동 메커니즘을 제품 장치로 번역

| 메커니즘 | 제품 장치 |
|---|---|
| 정보 갭 이론(호기심) | 연결마다 "왜 연결되는가" 한 문장 — 답을 다 주지 않고 갭을 남긴다 |
| 간헐적 강화(도파민) | "오늘 새로 바뀐 것"은 매일 다른 조합으로, 예측 불가능하게 |
| 기본값 설계(넛지) | 첫 화면은 요약만, 전체는 선택 — 인지 부하 최소화 |
| FOMO | "지금 움직이는 것"이 살아있다는 느낌(활성도 표시, 방금 갱신됨 타임스탬프) |
| 인지부조화 | 침묵지수·예상외 연결처럼 기존 믿음과 부딪히는 사실이 공유욕을 자극 |
| 확증편향 방지 | 침묵지수는 순수 관찰로만 제공, 특정 진영 해석에 이용되지 않도록 중립 유지 |
| 몰입(Flow) | 클릭마다 예측 가능한 구조가 즉시 나타나야 흐름이 끊기지 않는다 |
| 탐험욕 | 관계가 끊김 없이 계속 이어지는 느낌(스크롤/클릭에 다음이 항상 준비됨) |
| 학습욕 | 역사(타임라인)는 사실 나열이 아니라 서사로 — "왜 이렇게 흘러왔는가" |
| 수집욕 | 내가 추적하는 것들의 목록을 모으는 컬렉션 심리(팔로우, 후순위) |
| 비교심리 | 경쟁 관계에 있는 대상이 자연스럽게 옆에 노출 |
| SNS 심리 | 공유 카피는 "내가 먼저 알았다"는 정보 우월감을 자극 |
| 뉴스 소비 이중 욕구 | 짧게 훑고 싶은 욕구와 깊이 알고 싶은 욕구를 한 페이지 안에서 둘 다 충족 |
| 검색 심리 | 질문형 방문과 막연한 탐험형 방문 둘 다 같은 페이지가 착지점이 되도록 |

# 3. 탐험의 구조 — 시간이 흐를수록 사용자가 더 깊이 들어가게 만드는 설계

### 시간축별 경험
| 시점 | 목표 |
|---|---|
| 첫 3초 | "이건 뉴스 목록이 아니다"를 각인 |
| 첫 클릭 | 지연 없이 다음 화면 진입 |
| 첫 30초 | "지금 무슨 상황인지" 파악 완료 |
| 첫 3분 | 최소 한 번은 다른 대상으로 이동 |
| 첫 30분 | 5~10회 내부 탐색이 자연스럽게 발생 |
| 재방문 | "새로고침해도 뭔가 다르다"는 인상 |

### 모든 페이지가 공유하는 골격 — "지금 / 연결 / 역사"
어떤 대상(이슈든, 기업이든, 인물이든)에 들어가도 항상 같은 3가지 질문에 답한다:
1. **지금 무슨 상황인가** (현재 상태 — 확정/루머/미확정 구분)
2. **이것은 무엇과 연결되는가** (관계 — 반드시 "왜"가 붙은 한 문장과 함께)
3. **이것은 어떻게 여기까지 왔는가** (역사 — 사실 나열이 아니라 서사)

이 골격이 일관되게 유지되어야 사용자가 "여기서 뭘 더 볼 수 있는지"를 예측하며 안심하고 탐험한다 — 위키가 이걸 못 주는 이유는 문서마다 구조가 제각각이기 때문이다.

### 시간이 지날수록 가치가 커지는 구조
개별 기사는 시간이 지나면 가치가 떨어지는 휘발성 콘텐츠다. 반면 "지금/연결/역사"를 담은 페이지는 **시간이 지날수록 더 두꺼워진다** — 역사가 길어지고, 연결이 늘어나고, 근거가 쌓인다. 오래된 페이지일수록 더 가치 있는 구조 — 이게 뉴스 사이트와 결정적으로 다른 지점이며, 메이저 언론사가 쉽게 따라 하지 못하는 이유이기도 하다: 언론사의 자산은 "기사"고, 우리의 자산은 "누적되는 연결"이다. 후자는 시간을 아웃소싱할 수 없다.

### 검색엔진/위키가 못 하는 것, 우리가 하는 것
- 검색엔진: "질문 → 답 → 이탈"에 최적화. 우리는 "답 → 다음 질문 → 답"의 체인에 최적화한다.
- 위키: 중립적이고 정적이다, 분류(카테고리 트리)로 사고한다. 우리는 "지금 무엇이 움직이는가"로 살아있고, 분류가 아니라 관계로 사고한다.
- 그래서 메이저 언론이 못 따라 한다: 언론사 CMS는 기사를 발행하는 도구지 관계를 축적하는 도구가 아니다. 우리를 따라 하려면 조직 전체의 콘텐츠 모델을 바꿔야 하는데, 그건 기사 발행 조직에게 구조적으로 어렵다.

# 4. 정보가 연결되는 방식 (구조 — 사람 다음에 오는 도구)

- 무엇도 "최상위"가 아니다. 이슈든, 기업이든, 인물이든, 기술이든 전부 대등하게 연결된 대상(이하 "대상")이다.
- 개별 기사는 그 대상들을 증명하는 근거일 뿐 목적지가 아니다. 근거의 출처는 지금은 뉴스지만, 구조적으로 다른 소스(공시, 리서치)로 교체 가능해야 한다 — 뉴스저울이라는 이름을 떼도 성립해야 하기 때문이다.
- 대상과 대상 사이의 **관계**에는 항상 "왜 연결되는가"가 붙는다. 이게 링크와 관계의 차이다 — 링크는 목적지만 알려주고, 관계는 가야 할 이유를 알려준다.
- 대상의 **역사**는 별도 축으로 관리된다 — "관계"가 공간적 연결이라면 "역사"는 시간적 연결이다. 둘은 다른 질문에 답한다("무엇과 이어지는가" vs "어떻게 여기까지 왔는가").
- "오늘 새로 바뀐 것"은 하나의 대상에 갇히지 않고 여러 대상을 넘나드는 하나의 통합된 흐름으로 존재한다 — 나중에 "내가 관심 있는 것만 보기"를 얹을 때 이 흐름에 필터만 추가하면 되도록.
- 분류(카테고리)는 엄격한 트리가 아니라 느슨한 꼬리표다 — 엄격한 트리를 만드는 순간 위키의 사고방식으로 돌아간다.

# 5. AI가 개입하는 방식

- AI는 근거(기사)로부터 대상을 자동으로 식별하고, 대상들 사이의 관계를 자동으로 찾아내고, 그 관계를 "왜 연결되는가" 한 문장으로 표현한다 — 이 마지막 단계(설명 문장 생성)가 가장 어렵고 가장 중요하다. 단순 유사도 판단이 아니라 사람이 다음 클릭을 하고 싶어지는 문장을 쓰는 일이기 때문이다.
- AI는 확정된 사실과 미확인 루머를 구분해서 표기한다 — 이건 협상 불가능한 원칙이다(0장).
- AI는 스스로 만든 결과물의 품질을 채점하고, 기준 미달이면 재생성하거나 노출을 보류한다.
- 사람(관리자)은 AI가 확신하지 못하는 것들만 검토한다 — 전수 검토는 하지 않는다. "AI가 만들고 사람은 예외만 고친다"는 원칙의 실제 구현이다.
- AI가 쓰는 문장에는 **두 가지 서로 다른 목적**이 있고, 이 둘은 섞이면 안 된다:
  - 검색엔진/AI 검색이 인용하고 싶어지는 문장 — 짧고 스스로 완결됨.
  - 사람이 다음 클릭을 하고 싶어지는 문장 — 의도적으로 갭을 남김.
  이 두 문장은 서로 반대 성질을 가지므로 반드시 분리해서 관리한다.

# 6. 왜 사용자가 떠나지 않는가 — 종합

1. 완결된 답을 주지 않고 다음 질문을 남긴다(1·5장).
2. 어디를 가도 같은 골격("지금/연결/역사")이라 탐험이 예측 가능하고 피로하지 않다(3장).
3. 페이지는 시간이 지날수록 더 두꺼워진다 — 다시 봐도 늘 새로운 것이 있다(3장).
4. 관계에는 항상 이유가 붙어 있어 "그냥 링크"가 아니라 "따라가고 싶은 이유"가 있다(4장).
5. 비교·반박·의외성이 곳곳에 배치되어 인지적 자극이 끊이지 않는다(2장).
6. 광고·상업적 요소가 이 흐름을 방해하지 않도록 엄격히 분리된다(0장).

# 결정사항 — 구현 수준 판단은 여기서 확정하고 넘어간다

앞으로 이런 수준의 질문은 다시 묻지 않는다. 각 항목: 결정 / 이유 / 대안 / 향후 변경 가능성.

### 1. 노스스타 지표 = 세션당 탐험 깊이 + N일 재방문율
- **이유**: "기사 조회수"를 최적화하면 클릭베이트로 회귀한다. 이 제품의 본질은 "얼마나 멀리 따라가는가"다.
- **대안**: DAU, 단순 체류시간(탭 방치와 구분 안 됨).
- **변경 가능성**: 데이터 확보 후 상관관계 검증하며 보조 지표 추가 가능.

### 2. 분류(카테고리)는 트리가 아니라 느슨한 꼬리표
- **이유**: 트리를 엄격히 만드는 순간 위키의 사고방식으로 회귀한다. 연결은 관계로 만든다.
- **대안**: 계층형 카테고리 테이블.
- **변경 가능성**: 필터 UX에 트리형 내비게이션이 실제로 필요해지면 재검토.

### 3. "인용용 문장"과 "탐험 유도용 문장"을 분리 관리
- **이유**: AI 검색 인용은 닫힌 문장을 원하고, 탐험 유도는 열린 문장을 원한다 — 정반대 요구라 하나로 합칠 수 없다.
- **대안**: 하나의 텍스트를 상황별로 잘라 쓰기 — 품질 저하로 기각.
- **변경 가능성**: AI 검색발 유입 비중이 커지면 인용용 문장에 더 투자.

### 4. 광고는 트래픽/신뢰가 쌓인 뒤 도입, 탐험 흐름과 시각적으로 완전히 분리
- **이유**: 초기엔 신뢰 구축이 최우선. 광고가 탐험 경험을 해치면 노스스타가 훼손된다.
- **대안**: 초기부터 즉시 수익화.
- **변경 가능성**: 탐험 깊이 지표가 안정화되면 도입 시점을 앞당길 수 있음.

### 5. AI 생성물 사람 검토는 전수 검토가 아니라 저신뢰 항목만
- **이유**: 전수 검토는 "AI가 만들고 사람은 예외만 고친다"는 원칙과 충돌하고 운영 리소스를 과소모한다.
- **대안**: 모든 신규 항목을 사람이 승인 후 게시.
- **변경 가능성**: 오탐률이 예상보다 높으면 임계값을 낮춰 더 많이 큐잉.

### 6. 댓글/커뮤니티 기능은 후순위
- **이유**: 초기엔 콘텐츠 품질과 자동화 완성이 우선, 커뮤니티 운영은 별도 리소스를 요구한다.
- **대안**: 처음부터 최소 댓글 기능 포함.
- **변경 가능성**: 재방문율이 정체되고 비교·반박 심리를 더 자극할 장치가 필요해지면 앞당김.

### 7. "오늘 새로 바뀐 것"은 처음부터 여러 대상을 넘나드는 통합 흐름으로 설계
- **이유**: 하나의 대상에 종속된 피드로 만들면 나중에 "관심사만 보기"를 얹을 때 구조를 다시 짜야 한다.
- **대안**: 대상별 개별 로그만 유지하다가 나중에 통합.
- **변경 가능성**: 구조적 결정이라 나중에 바꾸는 비용이 크다 — 처음부터 이렇게 간다.

### 8. 근거(기사) 소스는 교체 가능한 레이어로 설계, 지금은 뉴스로 시작
- **이유**: "뉴스저울"이라는 이름을 떼도 성립해야 한다는 원칙(0장)의 직접적 구현.
- **대안**: 뉴스 전용 구조로 단순화.
- **변경 가능성**: 공시·특허·리서치 등 다른 근거 소스가 필요해지면 구조 변경 없이 추가.
