## 1. 핵심 UX 루프

```
카드 클릭 → 드로어 열림 → 다음 질문 클릭 → (드로어 내에서 계속 이어짐)
                              ↓ (더 깊이 읽고 싶을 때)
                        Question Detail (/story/[id])
                              ↓
                   Question Graph / 다음 질문 8~12개
                              ↓
                        (다른 질문으로 계속 이어짐)
```

이 루프가 끊기지 않는 것이 최우선 원칙. 과거(브랜드 Audit 시점) 드로어에서 기사 클릭 시 구브랜드 `/story` 페이지로 이탈하던 문제를 발견해 수정한 이력이 있음 — 앞으로 UX를 바꿀 때마다 "이 루프가 끊기지 않는가"를 체크한다.

## 2. 화면별 구조

### Hero
- 상단 "오늘의 무게" 라벨 + 저울 형태의 2-orb 비주얼(1위/2위 토픽 비교) + 캡션.
- **알려진 갭**: v5 목업(작은 추상 저울 아이콘 + 실시간 카운터 + 모멘텀 통계 버튼 3종)과 실제 구현(두 orb 직접 시각화)이 다름 — 브랜드 Audit에서 이미 발견, 우선순위 5번(급하지 않음)으로 보류 중. Hero 관련 변경은 승인 필요 항목.

### 매거진 그리드 (홈 카드)
- FeatureCard(피처, 3×2) / NodeCard(일반 이슈) / WeightCard / ConnectionCard(의외의 연결) 4종, `CardShell` 공통 쉘 기반.
- 반응형: Desktop(≥1025px) 6컬럼, Tablet(761–1024px) 4컬럼, Mobile(≤760px) 1컬럼 — 디자인 시스템 가이드 기준표 그대로 구현됨(`app/globals.css` `.nj-magazine-grid`).

### 드로어 (Explore Drawer)
- 데스크톱 우측 슬라이드(1025px+: 520px, 761–1024px: 440px), 모바일 하단 바텀시트(88vh, 상단 라운드 22px).
- 브레드크럼, 도메인 배지, 타이틀(Instrument Serif Italic), 본문, 태그, 관련 기사, "다음으로 이어지는 질문".
- `lib/drawer-data.ts`가 다음 질문을 **최소 6개까지 보장**(topic_relations 부족하면 다른 활성 토픽으로 패딩) — 단 이 패딩은 드로어 전용 정책, Question Detail의 Question Graph에는 적용 안 함(§3 참고).

### Question Detail (`/story/[id]`)
10섹션 순서(2026-07-10 확정):
1. 질문(대표 Topic 이름) 2. 오늘의 무게 3. 30초 이해 4. 왜 중요한가 5. 배경 설명 6. 우리에게 어떤 영향을 줄까? 7. 관련 기사 및 출처 8. 함께 연결된 Topic(최대 3개) 9. 사람들이 이어서 가장 많이 본 질문(8~12개) 10. Question Graph

세부 데이터 매핑과 설계 근거는 `lib/question-detail.ts` 코드 주석 및 커밋 이력(`804bfd9`) 참고.

## 3. Question Graph 원칙 (2026-07-10 확정)

- **절대 패딩하지 않는다** — 실제 `topic_relations`만 노드/엣지로 그린다. 연결이 적으면 적은 그대로 보여준다.
- 연결이 0개면 빈 영역 대신 안내 문구 노출: "아직 연결된 질문을 분석하는 중입니다."
- "다음 질문"(9번 섹션)은 패딩 허용(부족하면 다른 활성 토픽으로 채움) — Question Graph(10번)와는 다른 정책이니 혼동 금지.

## 4. 이미지 원칙

CTR 우선 — 아이콘/일러스트보다 **실사 이미지**를 우선한다(자세한 원칙은 [[뉴스저울 CTR 바이블]] 참고). 구현 메커니즘:
- 기사 원문의 `og:image` 재사용 (다운로드/재가공 없이 URL만 저장, 출처 링크 수준 사용)
- `CardShell`에 이미지 배경 + 하단 스크림 레이어 지원 추가됨(2026-07-10, 코드는 준비됐지만 `articles.og_image_url` DB 컬럼 마이그레이션이 아직 승인 대기라 비활성 상태)
- 이미지 없으면 기존 `SignatureCard`(색상+아이콘)로 자연 폴백 — 완전 대체 아님

## 5. 상세페이지 미디어 확장 여지

- `comparison` 콘텐츠 타입(`ComparisonCard`, `/compare/[slug]`)이 "임시 비주얼, 디자인팀 산출물 나오면 교체" 주석과 함께 이미 스캐폴딩돼 있음 — 향후 "비교 이미지" 요구사항은 여기에 자연스럽게 얹으면 됨.
- 차트는 실제 수치 데이터가 있을 때만(예: election 페이지 여론조사) — 없는 데이터로 그럴듯한 차트를 만들지 않는다(신뢰도 원칙).
