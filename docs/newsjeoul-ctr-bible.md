# 뉴스저울 CTR 바이블

> 이 문서는 뉴스저울의 공식 CTR(클릭률) 설계 기준입니다. 최종 수정: 2026-07-10.

## 0. 핵심 문장

**"브랜드는 클릭한 뒤에 기억된다. 클릭하기 전에는 콘텐츠가 먼저다."**

## 1. 4문항 테스트

모든 토픽/카드는 아래 4개 중 하나라도 "아니오"면 Hero·메인 피처카드에서 제외한다:
1. 내가 이걸 클릭할까?
2. 가족이나 친구가 궁금해할까?
3. Threads에서 멈춰서 읽을까?
4. 유튜브 썸네일이었다면 눌렀을까?

(상세 배경과 예시는 [[뉴스저울 콘텐츠 바이블]] §1 참고.)

## 2. 카드 디자인 원칙

- **실사 이미지가 아이콘/일러스트보다 우선.** 포르쉐면 실제 포르쉐 신형 사진, 인물이면 실제 인물 사진, 삼성전자면 실제 반도체 공장 사진 — "사용자가 스크롤을 멈추게 만드는" 실사가 목표.
- 아이콘/일러스트(`SignatureCard`)는 이미지가 없을 때만 쓰는 **폴백**이지, 기본값이 아니다.
- 구현 메커니즘·현재 상태는 [[뉴스저울 UX 바이블]] §4 참고.

## 3. Threads 카드 원칙

- 로고/브랜드 노출을 크게 하지 않는다. 뉴스저울 마크가 크게 보이는 것은 중요하지 않다.
- 대표 이미지를 최대한 크게, 화면을 거의 다 채운다.
- 질문은 짧고 강하게 — 한 줄로 눈에 박히는 카피.
- 브랜드 키트의 템플릿 프레임(레이아웃/컬러/타이포) 자체는 그대로 유지하고, 그 위에 사진만 얹는 구조. 프레임을 다시 디자인하지 않는다([[뉴스저울 UX 바이블]] §0, 디자인 잠금 원칙과 동일).

## 4. Hero 메가토픽 원칙

- Hero는 "오늘 가장 무거운 질문" 1개만 — 단발성 사건이 아니라 사람들이 계속 궁금해하는 화두여야 한다.
- 현재 임시 조치: 키워드 화이트리스트(`lib/topics.ts` `pickHeroTopic()`) — **이 로직 자체를 바꾸는 건 승인 필요 항목**([[뉴스저울 AI 편집국 바이블]] §승인 경계).
- 장기 목표: `topic_entities` 데이터가 쌓이면 "entity 재등장 빈도" 기반 자동 판별로 교체(화이트리스트 수동 관리 불필요하게).

## 5. 좋은 예시 / 나쁜 예시

**Hero/피처카드에 올릴 것(메가토픽, 질문형)**
GPT-6, AI, 트럼프, 이재명, 윤석열, 삼성전자, 엔비디아, 테슬라, 비트코인, 애플, 아이폰, 포르쉐, 현대차, 금리, 미국, 중국

**Hero/피처카드에서 제외할 것(저CTR, 행정/보도자료성)**
지자체 행사, ○○구 축제, ○○기관 보도자료, 단순 행정 공지, 지역 정책 홍보 — 예: "경기도 이주민 포털 공식 개통", "취약계층 반려동물 의료비 지원"
